# Forms Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let any page send a form to twillingate: forms are captured as
drafts, approved with expected fields, closed at a set time; submissions
are stored, shown as a filtered table, exported and erased, and an
approved form's submission is also a `$form_submit` conversion.

**Architecture:** One new ingest route (`POST /ingest/forms/{name}`) in
`internal/server` writes a submission (and, on an approved form, its
event) straight to SQLite in one transaction. Form management is audited
operations in `internal/manage`; the daily pass in `internal/jobs`
expires drafts. The console's custom-SQL handle refuses the `submissions`
table; the submissions table runs server-built SQL through `readsql`'s
existing filter/sort/page wrap on a second handle. The SDK gains a tagged
form and `submitForm`; the web app gains a Forms project tab.

**Tech Stack:** Go 1.x, modernc SQLite, `internal/shared/readsql`,
MCP go-sdk via `expose`; TypeScript SDK (vitest, esbuild bundle); React,
TanStack Query, shadcn UI, vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-05-forms-design.md` (D1–D12a).
Read it before each task; this plan says how, the spec says what.

## Global Constraints

- Go is at `/usr/local/go/bin` (not on PATH): `export PATH=/usr/local/go/bin:$PATH` before any `go` or `make`.
- Migration is `034_forms.sql` (latest on main is 033); migration test `migration034_test.go`.
- Form name: `^[a-z0-9_-]{1,64}$`. Anything else is a plain `400` with no redirect.
- Fragments, exact: `#twillingate-form-success-{name}` and `#twillingate-form-error-{name}`.
- Redirect order: `$redirect`, the form's `return_url`, the `Referer`; each only if allowed (D6). None allowed → plain `400`.
- Limits (in `internal/wire`): body 64 KiB, 100 fields, field name 64 characters, value 8 KiB (truncated, never refused).
- `FORMS_DRAFT_DAYS`: default 7, at least 1.
- `$form_submit` is written **only for approved forms**, with the submission's `id`, `ts = received_at`, family `product`, attribute `form` = the form name, and nothing else in attributes.
- Submissions are written in one transaction with their event, never through `pipeline.Buffer`.
- `submissions.fields` is a flat JSON object string→string; repeated form keys joined with `", "`; JSON arrays/objects/null drop the field; files discarded.
- The custom-SQL handle refuses `submissions`; `forms` stays readable.
- Commit messages: Conventional Commits, scopes from CLAUDE.md, imperative, lower case, no period; end every message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Docs change in the same commit as the code they describe (CLAUDE.md table). `internal/api/docs_sync_test.go` checks reserved event names, tools, routes, env vars, SDK symbols.
- Every clickable element in the web app is a `button`, a link or `role="button"`; no `cursor-pointer` classes (CLAUDE.md, `web/e2e/cursor.spec.ts`).
- No horizontal scroll at 360px (`web/e2e/phone.spec.ts`).
- `make check` must pass before the final push. After `sdk/` changes, `cd sdk && npm run build` and commit `internal/server/twillingate.js`.

## Review Focus

- `Origin: null` (pages with `Referrer-Policy: no-referrer`, sandboxed frames) on a form POST: treated like any origin not in `allowed_origins` (plain `403`), unless `allowed_origins` contains `null`, matching events. Test in Task 4.
- A form field named like a context key without `$` (`redirect`, `id`, `host`) is an ordinary field, never a context key; a `$`-field that is not a context key is dropped. Test in Task 4.
- A retried JSON submission with the same `id` after the form was approved stores once and does not emit a second event; a retry after the first succeeded returns `201` with the same id. Test in Task 2 and Task 4.
- A field name that collides with a fixed table column (`Received`, `Page`, `Referrer`, `UTM source`…) shows as `<name> (field)` and still filters and sorts. Test in Task 6.
- A `closes_at` in the past set on a draft, then the draft approved: it stays closed (approval does not reopen). Test in Task 5.
